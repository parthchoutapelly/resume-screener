### Underlying Accessibility Defects Resolved:
1. **WCAG 1.4.3 `color-contrast` (Serious):**
   - **Issue:** Secondary muted text (`--color-text-muted`) had insufficient contrast (~2.99:1) against dark surface backgrounds (`#111820`).
   - **Resolution:** Adjusted the design token in `frontend/src/styles/tokens.css` from `#576575` to `#8494A5`. This increased contrast to 5.75:1 against `#111820` and 6.19:1 against `#0B0F14`, meeting WCAG AA requirements ($\ge 4.5:1$) while preserving the dark recruiting-console aesthetic.
2. **WCAG 4.1.2 `link-name` (Serious):**
   - **Issue:** Test jobs lacking an explicit `job_title` rendered empty anchor tags (`<a href="/jobs/job_..."></a>`) without discernible accessible text.
   - **Resolution:** Introduced deterministic accessible title resolution via `getJobAccessibleTitle(job)` in `JobListPage.jsx`, falling back to `job.job_id` so that all interactive table links possess discernible visible text and explicit `aria-label` attributes.
3. **WCAG 4.1.2 `nested-interactive` (Serious):**
   - **Issue:** File dropzones in `FileDropZone.jsx` had a hidden file input nested inside an element with `role="button"` and `tabindex="0"`.
   - **Resolution:** Re-structured `FileDropZone.jsx` so the hidden `<input type="file" />` is rendered as an adjacent sibling to the interactive `role="button"` dropzone, eliminating nested interactive controls.
4. **W3C ARIA `aria-prohibited-attr` (Serious):**
   - **Issue:** Status badges in `StatusMark.jsx` applied `aria-label` directly to generic `<span>` elements without an explicit ARIA role.
   - **Resolution:** Added `role="img"` to the outer badge span in `StatusMark.jsx`, making `aria-label` compliant with ARIA in HTML specifications.
5. **Loading Spinner Semantics:**
   - **Resolution:** Added `role="status"` to loading spinner containers on `JobListPage.jsx`, `JobDetailPage.jsx`, and `FailedJobsPage.jsx`.

### Remaining Moderate Findings (Best Practices):
- **`/login` (2 moderate):** `landmark-one-main` (standalone authentication card not enclosed in `<main>` landmark); `region` (sub-content not partitioned into separate ARIA landmarks).
- **`/failed-jobs` (3 moderate):** `region` (secondary filtering toolbar not enclosed in dedicated landmark).
- **Critical / Serious:** **0** (All critical and serious defects fully resolved).

## 4. Keyboard Navigation & Focus Walkthrough (5 Screens)

The 5 application screens were verified for logical tab order, visible focus rings, and screen-reader accessibility:

### Screen 1: Sign-In / Authentication (`/login`)
- **Focus Elements:** 3 controls (`email` input, `password` input, `Sign In` button)
- **Accessible Names:** Non-empty, verified labels
- **Focus Rings:** High-contrast `focus-visible: outline 2px solid var(--accent)` applied to all interactive controls.

### Screen 2: Jobs Dashboard (`/jobs`)
- **Focus Elements:** 56 controls (Search input, New Job CTA, 25 interactive job rows and links, Sign Out)
- **Accessible Names:** All job row links have non-empty discernible titles (`getJobAccessibleTitle`)
- **Keyboard Operability:** Enter and Space keys trigger direct navigation to `/jobs/:jobId`.

### Screen 3: Create Job Posting (`/jobs/new`)
- **Focus Elements:** 16 controls (Inputs, radio buttons, file pickers, threshold slider, Submit)
- **Keyboard Operability:** Dropzone is focusable and activates file picker on Enter/Space; hidden inputs are decoupled siblings.

### Screen 4: Job Detail & Candidate Scoring (`/jobs/:jobId`)
- **Focus Elements:** 42 controls (Tabs, search, candidate decision buttons, export CSV, drawer toggle)
- **Accessibility:** Status badges have `role="img"` with descriptive labels; decision buttons have explicit `aria-label`.

### Screen 5: Admin Failed Jobs (`/failed-jobs`)
- **Focus Elements:** 12 controls (Filter controls, failure items, retry actions, Sign Out)
- **Accessibility:** Error codes and diagnostic traces presented in accessible monospace blocks with descriptive accessible names.
